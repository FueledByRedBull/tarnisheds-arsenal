# Release v0.8.1

GitHub release: [Tarnished's Arsenal v0.8.1](https://github.com/FueledByRedBull/tarnisheds-arsenal/releases/tag/v0.8.1)

v0.8.1 contains the complete v0.8.0 feature and hardening release. The v0.8.0
tag was not published after its hosted packaged-app smoke could not observe the
WebView2 debugging endpoint, despite all compile, test, data, and bundle gates
passing.

- Reserve an available loopback port for packaged WebView2 smoke automation
  instead of guessing from a small fixed range.
- Give every launch a unique WebView2 data directory so an existing browser
  process cannot discard the requested debugging arguments.
- Add bounded startup retries, early process-exit detection, endpoint identity
  validation, GPU-independent runner arguments, temporary-profile cleanup, and
  per-attempt diagnostics.
- Preserve the full packaged workflow assertion: native search, selection below
  the podium, Compare, Paths, Affinity Watch, and saved-build reload.

## Changes carried from v0.8.0

The unpublished v0.8.0 candidate supplied the following product changes; v0.8.1
added the release-smoke fixes above.

- Harden Search, Compare, Paths, Affinity Watch, profiles, and shared analysis
  caches with exact request generations, cancellation propagation, adaptive
  non-overlapping polling, bounded LRU/TTL storage, and stale-result rejection.
- Define a 250 ms broad-search cancellation target and add deterministic core and
  Tauri regressions that reject partial cancelled workflow payloads.
- Hard-bound optimizer candidate retention under large equal-score cutoffs while
  lazily completing final tie-break fields, preserving exact ordering and
  serial/parallel equivalence without unbounded memory growth.
- Add reusable direct evaluators for fixed loadouts, upgrade series, Paths, and
  multi-level Affinity Watch. Standard/somber, sparse reinforcement, native skill,
  request identity, and independent-search equivalence are covered by tests.
- Split release benchmarking into preparation, scoring/top-k, and final
  materialization phases with per-phase medians, machine/data/model/build metadata,
  and advisory baseline comparisons.
- Deep-validate and migrate saved builds across schema, dataset, and model versions;
  make import conflicts, size limits, stale state, delete/undo, and clipboard
  failures explicit.
- Improve the responsive Rankings, Compare, Paths, Affinity Watch, and Build Detail
  experience with clearer prerequisites, loading/dirty states, semantic tables and
  charts, keyboard/screen-reader coverage, high-DPI handling, and model disclosures.
- Expand release engineering with strict Rust/Python/TypeScript/data gates,
  curated embedded snapshots, deterministic frontend setup, optional fail-closed
  Windows signing, provenance reports, and a real packaged-app save/load smoke.
- Refresh the README with a product workflow diagram, current objective coverage,
  architecture links, and release-mode performance guidance.

The v0.8.0 candidate notes recorded 89 Rust core tests, 16 active Tauri tests
(plus three ignored release benchmarks), 30 Vitest tests, 10 Playwright contracts,
strict formatting/lint/type checks, zero-warning data validation, and EXE/MSI
builds. Hosted packaged-smoke verification prevented publication of that candidate,
as described above.
