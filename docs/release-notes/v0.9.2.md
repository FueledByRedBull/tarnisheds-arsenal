# Release v0.9.2

GitHub release: [Tarnished's Arsenal v0.9.2](https://github.com/FueledByRedBull/tarnisheds-arsenal/releases/tag/v0.9.2)

v0.9.2 removes expensive optimizer work from stat-field editing, accelerates exact
search-space preparation, and makes scaling and status comparisons complete and
readable throughout the desktop interface.

> **Convergence coverage remains beta; v0.9.2 is a stable application release.**
> Melee weapon AR, status, passives, affinities, compatibility, and extended grades
> remain supported for Convergence 3.0.0.1. Ammunition weapon AR and Convergence
> Ash of War hit/route damage remain disabled until their profile-specific models
> are validated.

- Keep numeric inputs as local drafts while typing. Valid values commit after 700
  ms idle, on blur, or on Enter; exact optimizer preparation begins only after the
  user presses Search.
- Make exact estimates cancellable and reuse distribution counts shared by
  identical stat bounds. Estimation skips scoring-work materialization and uses a
  direct arithmetic weapon-requirement feasibility check.
- Preserve exact search counts and results. On the reference machine, representative
  high-level estimates dropped from roughly 0.82-3.10 seconds to 0.046-0.117
  seconds, approximately 17-27x faster.
- Replace the truncated scaling string with centered STR, DEX, INT, FAI, and ARC
  tokens that adapt to the available ranking width.
- Replace the hardcoded Bleed/Frost summary with all seven passive statuses: Bleed,
  Frost, Poison, Scarlet Rot, Sleep, Madness, and Death Blight. Zeroes stay visible
  so absent buildup is not confused with omitted data.
- Show Physical, Magic, Fire, Lightning, and Holy AR components directly in every
  ranking row, including explicit zeroes, without hiding them behind another view.
- Center and wrap ranking headers so labels stay aligned with their columns instead
  of truncating at narrower window sizes.
- Retry the native Tauri bundling step with bounded backoff so a transient WiX
  download interruption does not discard an otherwise validated release build.
- Use the same accessible scaling/status presentation in Rankings, Compare, and
  Build Detail, with full names available to assistive technology.
- Carry Sleep, Madness, and Death Blight through the Rust optimizer, Python binding,
  Tauri DTOs, frontend model, compatible saved-build migration, and CSV output.
- Reuse solved-row scaling in Rankings and Compare, eliminating one backend scaling
  request per displayed result.
- Add estimator equivalence/cancellation benchmarks, real Sleep/Madness
  materialization coverage, saved-build migration validation, CSV checks, and
  server-rendered accessibility regressions.
