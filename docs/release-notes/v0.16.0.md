# Release v0.16.0

[Home](https://github.com/FueledByRedBull/tarnisheds-arsenal/blob/v0.16.0/README.md) · [All releases](https://github.com/FueledByRedBull/tarnisheds-arsenal/blob/v0.16.0/docs/release-notes/README.md)

A refreshed desktop layout, corrected skill routes, and saved builds that load and
verify reliably.

## Desktop

- Rankings rows show each result's loadout, weapon scaling, combat stats, AR, and
  skill damage, with stat keys aligned to the column headers. AR is shown to one
  decimal in Rankings, Build Detail, and Compare alike.
- Game profile selection moves into the command rail beside the build inputs,
  with its model coverage notes.
- Semantic colours distinguish information, warnings, errors, and successes.
  Loading placeholders replace blank panels while game data and weapon details
  load, and transitions respect the system reduced-motion setting.
- Saved Builds gains a compact action toolbar, with importing in its own
  disclosure. Stat Budget reads as movable, unspent, and total points, and Paths
  uses **Levels ahead** and **Best per level**.

## Skill calculations

- Keep weapon-restricted transferable skills under their own skill IDs: Wing
  Stance on Milady is no longer treated as an Impaling Thrust variant.
- Give numbered charge levels, such as Carian Grandeur's two charged levels, and
  near/far projectile phases their own routes. Glintstone Dart's thrust can follow
  either charge state.
- Restrict skill routes to the weapon's resolved one- or two-handed handling
  before scoring, including reusable loadout analyses.
- Show a missing per-build skill calculation as unavailable, with a blank CSV
  value, instead of zero damage. A calculated route whose damage is zero keeps
  that zero.

See the [model reference](https://github.com/FueledByRedBull/tarnisheds-arsenal/blob/v0.16.0/docs/model-reference.md)
and [optimizer mathematics](https://github.com/FueledByRedBull/tarnisheds-arsenal/blob/v0.16.0/docs/design/optimizer-math.md)
for route rules, formulas, and assumptions.

## Saved builds and workflows

- Recalculate saved results on current data before showing them. Each pinned
  comparison is verified at the level its own stats require, so builds pinned from
  a higher-level search load instead of failing.
- Validate saved starting classes before activation, keep saved builds when
  rendering or storage fails, and wait for game data before loading a build.
- Keep comparison pins and saved comparison targets when reopening Compare and
  Paths. Show verified comparison lanes before optional charts, and show lower
  stamina costs as improvements.
- Reject unavailable exact upgrade levels, keep explicit +0-only pinned
  comparisons, and report missing Affinity Watch endpoints as unavailable.
- Fix weapon selector commit ordering and stale weapon details, include forced
  two-handing in displayed requirements, and give the starter search coherent
  filters. Reduce Affinity Watch payloads and repeated catalog work.

## Data compatibility and limits

Both bundled profiles are regenerated with snapshot schema **6** and runtime model
**`aow-routes-effects-v9/exact-v3`**. Solved results saved with an earlier model
load as inputs only, so they cannot be mistaken for results from the corrected
routes; saved inputs remain reusable. The game profiles remain Vanilla **1.17**
and Convergence **3.0.0.1**. Convergence retains its documented experimental
feature limits.

AR and status values do not include enemy defenses, resistance growth, or status
proc damage. Sequence totals assume the modeled contacts connect. War Cry and
Barbaric Roar's attack-power self-buffs are not modeled. This release does not
claim live in-game verification of every skill.

## Verification

The release source passed 241 core tests, 61 backend tests, 175 frontend unit
tests, 146 browser tests, and 17 Node contract checks; release-mode benchmarks,
which are opt-in, were not run. Frontend lint
and the production build, both snapshot validators, 122 Python extraction and
validation-tool tests, release metadata validation, and documentation link checks
also passed. Five packaging tests that need PowerShell 7 were skipped locally and
run in CI.

A debug native build of the same application source passed the packaged WebView2
smoke test before the version bump. CI now runs that smoke test on every change.
A seeded external reference comparison against the pinned T. Clark 1.17
calculator passed all 632 Vanilla weapon AR and base status cases, covering 100
weapons and the 32 Bloodfiend's Fork boundary cases at zero, random, and maximum
upgrades in both handling modes. The largest AR component difference was
0.00008, within the 0.001 tolerance, and all 348 applicable selected-skill
identities matched. It does not check skill damage formulas; the exhaustive
comparison was not rerun.
Versioned packages must pass the release workflow's package checks before
publication. Installation, upgrade, and uninstall on a clean Windows machine were
not exercised. The release build report records the final source commit, package
checks, and signing status.
